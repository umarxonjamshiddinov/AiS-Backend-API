# AiS Backend API

An OpenAI-compatible API gateway that you can run on your own infrastructure. The backend, PostgreSQL database, administrator credentials, provider credentials, and client API keys belong to your deployment; no AiS-hosted account or API endpoint is required.

## Features

- OpenAI-compatible `GET /v1/models` and `POST /v1/chat/completions`.
- Browser-based administration at `/admin` for users, API keys, model routes, provider credentials, and usage.
- PostgreSQL-backed key ownership, model permissions, quotas, usage records, and migrations.
- Amazon Bedrock Converse and Bedrock Mantle adapters. Provider credentials are optional until you enable inference.
- Per-deployment API base URL configuration; no production API hostname is built into the admin panel.
- A bundled vanilla JavaScript admin interface served by the backend; it has no separate Node build step.

## Architecture and technology

FastAPI serves the public API and same-origin admin UI. SQLAlchemy and Alembic manage PostgreSQL data and schema migrations. Provider adapters route configured model aliases to Amazon Bedrock. The browser sends admin requests to the same deployment origin; the admin token remains in page memory. Client API keys are generated by the local instance and stored as hashes.

The admin UI is in `app/static/`. `app/public_portal/` contains a separate prebuilt documentation portal bundle; it is not required to run the API or admin panel. The backend's admin UI does not require an npm install or frontend build.

## Prerequisites

- Python 3.13 or newer.
- PostgreSQL, including a separate local test database if you want to run the full integration suite.
- Git.
- Node.js for the admin JavaScript syntax and DOM regression checks; it is not needed to serve the application.
- `uv` is optional and is only needed for the `uv audit` dependency check.
- Amazon Bedrock access and a supported server-side credential only if you intend to make inference requests. Calls may incur provider charges.

## Installation

Clone the existing repository and enter its directory:

```shell
git clone https://github.com/umarxonjamshiddinov/AiS-Backend-API.git
cd AiS-Backend-API
```

### Windows PowerShell

The optional local PostgreSQL helper expects installed PostgreSQL binaries (by default under `C:\Program Files\PostgreSQL\18\bin`). Set `POSTGRES_BIN` before running it if the binaries are elsewhere; the older `AIS_POSTGRES_BIN` variable remains supported.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e ".[dev]"
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Put the generated random value in `.env` as `ADMIN_TOKEN`. For automatic local database creation, leave `DATABASE_URL` and `TEST_DATABASE_URL` empty in `.env`, then run:

```powershell
.\.venv\Scripts\python.exe scripts\setup_local_db.py
.\.venv\Scripts\python.exe -m app.manage init-db
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Alternatively, `.\scripts\start.ps1` performs local database setup, migrations, catalog seeding, and starts Uvicorn. Use `.\scripts\start.ps1 -SkipLocalDatabaseSetup` with an already configured `DATABASE_URL`.

### Linux and macOS

Create a Python environment and install the pinned dependencies:

```shell
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.lock.txt
python -m pip install --no-deps -e '.[dev]'
cp .env.example .env
python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Set the generated random value as `ADMIN_TOKEN` in `.env`. Provision PostgreSQL using your local package/service manager. For a local PostgreSQL installation using its `postgres` operating-system account, create a role and two databases:

```shell
sudo -u postgres createuser --pwprompt ais_owner
sudo -u postgres createdb --owner=ais_owner ais
sudo -u postgres createdb --owner=ais_owner ais_test
```

Set `DATABASE_URL` and `TEST_DATABASE_URL` in `.env` to the corresponding `postgresql+psycopg://` URLs (URL-encode special characters in passwords). Apply migrations and start the backend:

```shell
python -m app.manage init-db
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`init-db` applies Alembic migrations and inserts missing bundled model-catalog rows. It does not create PostgreSQL roles or databases.

## Environment configuration

Copy `.env.example` to `.env`; never commit `.env` or put real credentials in the example file.

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection for the running application. Required for database-backed API/admin operations. |
| `TEST_DATABASE_URL` | Separate local PostgreSQL database named `ais_test`; integration tests create and drop isolated schemas there. Never point it at production. |
| `ADMIN_TOKEN` | Secret bearer token for `/admin/api` and the `/admin` login. Generate a unique value and keep it private. |
| `PUBLIC_API_BASE_URL` | Optional public endpoint shown when a key is issued, e.g. `https://ai.example.com/v1`. The application appends `/v1` if omitted. |
| `OPENAI_API_KEY` | Legacy-named server-side Amazon Bedrock Mantle bearer credential; this project does not use it as an OpenAI provider key. |
| `AWS_BEARER_TOKEN_BEDROCK` | Server-side Bedrock Converse credential and legacy Mantle fallback when `OPENAI_API_KEY` is empty. |
| `OPENAI_BASE_URL` | Bedrock Mantle upstream setting. The application validates it against the supported Bedrock Mantle host; it is not the public client endpoint. |
| `AWS_REGION`, `BEDROCK_MODEL_ID` | Defaults for the Bedrock Converse adapter. Mantle routes use the region and route saved with each model. |
| `AI_DEFAULT_MAX_OUTPUT_TOKENS`, `AI_REQUEST_TIMEOUT_SECONDS`, `AI_RETRY_COUNT`, `AI_RETRY_BACKOFF_SECONDS` | Inference output and retry/time limits. |
| `VISION_HELPER_MODEL_KEY`, `MODERATION_MODEL_KEY` | Model aliases used by internal helper paths. |
| `RESERVATION_TTL_SECONDS`, `RESERVATION_HEARTBEAT_SECONDS`, `RESERVATION_REAPER_SECONDS` | Usage reservation and recovery timing. |

You do not need to configure provider credentials to start the backend, open `/admin`, or manage users and keys. Inference returns a provider-not-configured error until a supported provider is configured. The admin provider form saves the selected server-side credential to `.env`; protect that file and the host filesystem.

## Database setup and migrations

The runtime database must be PostgreSQL. `python -m app.manage init-db` runs `alembic upgrade head` and then inserts missing catalog rows without replacing existing database edits. `python -m app.manage sync-models` repeats only the idempotent catalog seed. Back up the database before applying migrations to an existing deployment.

For tests, configure `TEST_DATABASE_URL` to a separate local database named `ais_test`. The test fixture refuses other database names or non-loopback hosts before creating a temporary schema. If this variable is absent, PostgreSQL integration tests are reported as skipped; CI provisions the test database.

## Starting the backend and opening the admin panel

Start the backend using the command for your platform above, then open `http://127.0.0.1:8000/admin` in a browser and sign in with `ADMIN_TOKEN`. The UI and `/admin/api` use the same origin; no CORS or separate frontend server is required for the bundled admin panel.

Create an initial local user through the management CLI:

```powershell
.\.venv\Scripts\python.exe -m app.manage create-user --name owner
```

```shell
python -m app.manage create-user --name owner
```

The command is idempotent for a username. Administrators can also create users in the panel. Client API keys can be created from the panel or CLI; their complete value is returned only once.

## Custom API base URL and reverse proxies

Set `PUBLIC_API_BASE_URL` to the endpoint clients should use, for example:

```dotenv
PUBLIC_API_BASE_URL=https://ai.example.com/v1
```

With this setting, the admin footer and the newly-issued-key dialog show the configured endpoint. If it is unset, the application derives the endpoint from the ASGI request scheme, `Host` header, configured `root_path`, and `/v1`. It does not directly consume `X-Forwarded-Host` or `X-Forwarded-Proto`.

For a reverse-proxy deployment, preserve the public `Host` header and configure Uvicorn to trust proxy headers only from the actual proxy address. For example, when the proxy connects from loopback:

```shell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
```

Replace the loopback address with the proxy's actual trusted IP or range; do not use `*` on an exposed listener. Uvicorn's trusted proxy middleware can set the ASGI scheme from forwarded protocol information. If the proxy topology, external hostname, or mount path makes automatic derivation unsuitable, set `PUBLIC_API_BASE_URL` explicitly. The same value is returned to the admin UI and is the endpoint to use with issued keys.

## Configure AI providers

The current adapters are Amazon Bedrock Converse (`bedrock`) and Bedrock Mantle (`amazon_bedrock`). They require valid credentials and model/region access from AWS. No AiS account, endpoint, or credential is needed. The application does not currently implement a general OpenAI, Anthropic, or OpenRouter upstream adapter.

Configure credentials either in `.env` before startup or in the authenticated admin panel's **Providers** section. For Mantle, the legacy `OPENAI_API_KEY` environment variable is used for the Bedrock Mantle bearer token; `AWS_BEARER_TOKEN_BEDROCK` is accepted as its fallback. For Converse, use `AWS_BEARER_TOKEN_BEDROCK`. Do not put downstream client API keys in either provider variable.

## Create users and API keys

Create the user and a client key locally:

```powershell
$issued = .\.venv\Scripts\python.exe -m app.manage create-key --user owner --name local-client | ConvertFrom-Json
$env:API_KEY = $issued.key
```

```shell
python -m app.manage create-key --user owner --name local-client
```

On Linux/macOS, capture the one-time JSON response without printing the key:

```shell
API_KEY="$(python -m app.manage create-key --user owner --name local-client | python -c 'import json,sys; print(json.load(sys.stdin)[\"key\"])')"
```

The key is generated by your instance and works only against that instance. The database stores its hash, not the complete key. Treat the one-time CLI output like a password; revoke a key if it is exposed.

## API usage

Set `API_BASE_URL` to your own configured public URL, or use the local default:

```powershell
$env:API_BASE_URL = 'http://127.0.0.1:8000/v1'
$headers = @{ Authorization = "Bearer $env:API_KEY" }
Invoke-RestMethod -Uri "$env:API_BASE_URL/models" -Headers $headers
```

```shell
API_BASE_URL="${PUBLIC_API_BASE_URL:-http://127.0.0.1:8000/v1}"
curl --fail-with-body "$API_BASE_URL/models" -H "Authorization: Bearer $API_KEY"
```

Example chat request:

```powershell
$body = @{ model = 'xai.grok-4.3'; messages = @(@{ role = 'user'; content = 'Reply with exactly OK.' }) } | ConvertTo-Json -Depth 6
Invoke-RestMethod -Method Post -Uri "$env:API_BASE_URL/chat/completions" -Headers $headers `
  -ContentType 'application/json' -Body $body
```

```shell
curl --fail-with-body "$API_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"xai.grok-4.3","messages":[{"role":"user","content":"Reply with exactly OK."}]}'
```

Chat requests can incur provider charges. Check model access, permissions, quotas, and provider billing before sending them. `/v1/models` does not invoke inference.

## Security considerations

- Use HTTPS for deployments and a high-entropy `ADMIN_TOKEN`; restrict access to `/admin` and the admin API at your network boundary.
- Keep `.env`, provider credentials, database credentials, backups, logs, and local database files out of source control.
- Configure reverse-proxy trust narrowly. Do not trust arbitrary forwarded headers or expose a proxy-header-enabled Uvicorn listener to untrusted clients.
- Create client keys with only the required model permissions and quotas; revoke keys promptly when no longer needed.
- Provider access and inference may incur charges. Configure AWS entitlements, limits, and monitoring independently.
- Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md).

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Database connection or migration error | Confirm PostgreSQL is running, `DATABASE_URL` is correct, and the role can create/use the application schema. |
| `/admin` says admin is not configured | Set a non-empty `ADMIN_TOKEN` in the process environment or `.env`, then restart the backend. |
| Key dialog shows an unexpected endpoint | Set `PUBLIC_API_BASE_URL`; otherwise verify the request `Host`, ASGI scheme, `root_path`, and explicitly trusted proxy configuration. |
| Model request reports provider not configured | Configure the server-side Bedrock credential and verify AWS model/region access. |
| Some tests skip | Set `TEST_DATABASE_URL` to a separate local PostgreSQL database named `ais_test`; do not use production. |
| Local Windows database setup cannot find PostgreSQL | Install PostgreSQL command-line/server binaries or set `POSTGRES_BIN` to the installed `bin` directory. |

# AiS Backend API — русская версия

OpenAI-совместимый API-шлюз, который можно развернуть на собственной инфраструктуре. Backend, база PostgreSQL, учётные данные администратора и провайдера, а также клиентские API-ключи принадлежат вашему экземпляру; учётная запись, API endpoint или инфраструктура AiS не требуются.

## Возможности

- OpenAI-совместимые `GET /v1/models` и `POST /v1/chat/completions`.
- Веб-панель администратора по адресу `/admin`: пользователи, API-ключи, маршруты моделей, credentials провайдера и статистика использования.
- PostgreSQL-хранение владельцев ключей, разрешений моделей, квот и записей использования; миграции схемы.
- Адаптеры Amazon Bedrock Converse и Bedrock Mantle. Credentials провайдера не нужны до включения inference.
- Настраиваемый API Base URL для каждого развертывания; production endpoint AiS не зашит в панель.
- Vanilla JavaScript-панель включена в backend и не требует отдельной сборки Node.

## Архитектура и технологии

FastAPI обслуживает публичный API и панель администратора на том же origin. SQLAlchemy и Alembic управляют данными PostgreSQL и миграциями. Адаптеры направляют настроенные aliases моделей в Amazon Bedrock. Браузер отправляет admin-запросы на тот же origin; admin token хранится только в памяти страницы. Клиентские API-ключи создает локальный экземпляр, в базе сохраняются их хеши.

Исходники панели находятся в `app/static/`. `app/public_portal/` содержит отдельную предварительно собранную документационную страницу; для API и админки она не нужна. Для панели не нужны npm install и сборка frontend.

## Требования

- Python 3.13 или новее.
- PostgreSQL; для полного набора интеграционных тестов нужна отдельная локальная тестовая база.
- Git.
- Node.js нужен для проверки синтаксиса JavaScript и DOM regression-теста панели; для запуска приложения он не нужен.
- `uv` необязателен и нужен только для проверки зависимостей командой `uv audit`.
- Доступ к Amazon Bedrock и поддерживаемый серверный credential нужны только для inference. Вызовы могут тарифицироваться провайдером.

## Настройка базы и миграции

Для работы приложения требуется PostgreSQL. `python -m app.manage init-db` выполняет `alembic upgrade head` и добавляет отсутствующие строки каталога, не перезаписывая существующие изменения в базе. `python -m app.manage sync-models` повторно выполняет только идемпотентное заполнение каталога. Перед миграцией существующей установки сделайте резервную копию.

Для тестов настройте `TEST_DATABASE_URL` на отдельную локальную базу `ais_test`. Фикстура откажется работать с другим именем базы или нелокальным хостом и создаёт временную схему. Если переменная не задана, интеграционные тесты PostgreSQL будут пропущены с явным сообщением; CI поднимает тестовую базу автоматически.

## Собственный API Base URL и reverse proxy

Задайте `PUBLIC_API_BASE_URL` — endpoint, которым будут пользоваться клиенты, например:

```dotenv
PUBLIC_API_BASE_URL=https://ai.example.com/v1
```

При этой настройке footer админки и диалог созданного ключа показывают заданный endpoint. Если переменная пустая, приложение формирует URL из схемы ASGI-запроса, заголовка `Host`, настроенного `root_path` и `/v1`. Заголовки `X-Forwarded-Host` и `X-Forwarded-Proto` напрямую приложением не читаются.

При развертывании за reverse proxy сохраняйте публичный заголовок `Host` и настройте Uvicorn доверять proxy headers только от реального адреса прокси. Например, если proxy подключается с loopback:

```shell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
```

Замените loopback на реальный доверенный IP или диапазон прокси; не используйте `*` на доступном извне listener. Доверенный proxy middleware Uvicorn может передать схему из заголовка протокола. Если схема proxy, внешний hostname или mount path не подходят для автоматического определения, явно задайте `PUBLIC_API_BASE_URL`. Это значение показывается в админке и является endpoint для созданных ключей.

## Настройка AI-провайдеров

Текущие адаптеры — Amazon Bedrock Converse (`bedrock`) и Bedrock Mantle (`amazon_bedrock`). Нужны действующие AWS credentials и доступ к модели/региону. Учётная запись, endpoint или credential AiS не требуются. Сейчас в проекте нет общего upstream-адаптера OpenAI, Anthropic или OpenRouter.

Настройте credentials в `.env` до запуска или в разделе **Providers** панели администратора. Для Mantle историческая переменная `OPENAI_API_KEY` используется как Bedrock Mantle bearer token; `AWS_BEARER_TOKEN_BEDROCK` поддерживается как fallback. Для Converse используйте `AWS_BEARER_TOKEN_BEDROCK`. Не помещайте клиентские API-ключи в переменные credential провайдера.

## Создание пользователей и API-ключей

Создайте пользователя и клиентский ключ локально:

```powershell
$issued = .\.venv\Scripts\python.exe -m app.manage create-key --user owner --name local-client | ConvertFrom-Json
$env:API_KEY = $issued.key
```

```shell
python -m app.manage create-key --user owner --name local-client
```

В Linux/macOS можно получить одноразовый JSON-ответ в переменную, не выводя ключ:

```shell
API_KEY="$(python -m app.manage create-key --user owner --name local-client | python -c 'import json,sys; print(json.load(sys.stdin)[\"key\"])')"
```

Ключ создаёт ваш экземпляр, и он работает только с этим экземпляром. В базе хранится хеш, а не полный ключ. Одноразовый вывод CLI храните как пароль; при утечке отзовите ключ.

## Использование API

Задайте `API_BASE_URL` равным вашему публичному endpoint или используйте локальное значение по умолчанию:

```powershell
$env:API_BASE_URL = 'http://127.0.0.1:8000/v1'
$headers = @{ Authorization = "Bearer $env:API_KEY" }
Invoke-RestMethod -Uri "$env:API_BASE_URL/models" -Headers $headers
```

```shell
API_BASE_URL="${PUBLIC_API_BASE_URL:-http://127.0.0.1:8000/v1}"
curl --fail-with-body "$API_BASE_URL/models" -H "Authorization: Bearer $API_KEY"
```

Пример запроса чата:

```powershell
$body = @{ model = 'xai.grok-4.3'; messages = @(@{ role = 'user'; content = 'Reply with exactly OK.' }) } | ConvertTo-Json -Depth 6
Invoke-RestMethod -Method Post -Uri "$env:API_BASE_URL/chat/completions" -Headers $headers `
  -ContentType 'application/json' -Body $body
```

```shell
curl --fail-with-body "$API_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"xai.grok-4.3","messages":[{"role":"user","content":"Reply with exactly OK."}]}'
```

Chat-запросы могут тарифицироваться провайдером. Перед отправкой проверьте доступность модели, разрешения, квоты и биллинг провайдера. `/v1/models` не вызывает inference.

## Безопасность

- Используйте HTTPS, случайный длинный `ADMIN_TOKEN` и ограничьте сетевой доступ к `/admin` и admin API.
- Не добавляйте `.env`, credentials провайдеров и БД, резервные копии, логи и файлы локальной БД в Git.
- Ограничивайте доверие reverse proxy. Не доверяйте произвольным forwarded headers и не открывайте Uvicorn с proxy headers для недоверенных клиентов.
- Выдавайте клиентским ключам только необходимые разрешения и квоты; своевременно отзывайте неиспользуемые ключи.
- Использование провайдера и inference могут тарифицироваться. Настройте AWS-доступ, лимиты и мониторинг отдельно.
- Сообщайте об уязвимостях приватно согласно [SECURITY.md](SECURITY.md).

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Ошибка подключения к БД или миграции | Убедитесь, что PostgreSQL запущен, `DATABASE_URL` корректен, а роль имеет доступ к схеме приложения. |
| `/admin` сообщает, что admin не настроен | Задайте непустой `ADMIN_TOKEN` в окружении процесса или `.env`, затем перезапустите backend. |
| В диалоге ключа отображается неверный endpoint | Задайте `PUBLIC_API_BASE_URL`; иначе проверьте `Host`, схему ASGI, `root_path` и явную настройку доверенного proxy. |
| Запрос модели сообщает, что провайдер не настроен | Настройте серверный Bedrock credential и проверьте AWS-доступ к модели/региону. |
| Часть тестов пропущена | Укажите `TEST_DATABASE_URL` локальной PostgreSQL-базы `ais_test`; не используйте production. |
| Windows setup не находит PostgreSQL | Установите серверные/CLI-бинарники PostgreSQL либо задайте `POSTGRES_BIN` на каталог `bin`. |
